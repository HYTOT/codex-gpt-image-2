# 参考图生图操作手册

本文档用于指导协作人员在当前工程中执行新的生图需求，尤其是带有不定数量参考图的场景。

## 适用场景

- 纯文本生图：`reference_images=[]`
- 单张参考图生图：`reference_images` 中只有 1 张图片
- 多张参考图生图：`reference_images` 中有 2 张及以上图片
- 多参考图 + mask 编辑：`reference_images` 非空，且 `mask_image` 非空

## 执行前准备

开始前请确认：

- 已在 `.env` 中配置 `OPENAI_API_KEY`
- 所有路径都使用项目内相对路径，不要填写本机绝对路径
- 参考图和 mask 仅支持：`.png`、`.jpg`、`.jpeg`、`.webp`
- 建议把“主体角色 / 主体风格 / 主构图”的主参考图放在 `reference_images` 第 1 位
- 需要协作复制时，优先从 `configs/` 下的示例配置复制，不直接改历史输出目录

推荐做法：

- 为每次真实需求单独创建 `tasks/<任务名>/` 目录
- 将 `task.json`、变量文件、参考图、可选 mask 都放在该任务目录内
- 让 `configs/task.json` 只保留一个 `task_file` 指针，指向本次要执行的任务

## 标准操作步骤

1. 准备提示词变量文件，例如 `prompts/variables/example.json`
2. 准备参考图和可选 mask，并放到项目目录内
3. 从 `configs/task.example.json`、`configs/task.multi-reference.example.json` 或 `configs/task.multi-reference-mask.example.json` 复制一份为 `configs/task.json`
4. 按本次需求修改 `prompt_name`、`prompt_version`、`variables_file`、`reference_images`、`mask_image`
5. 执行 `python main.py`
6. 到最新任务目录中检查图片、提示词、请求摘要、响应摘要和日志

如使用任务目录机制，建议替换为：

1. 新建 `tasks/<任务名>/`
2. 在任务目录下准备 `task.json`、变量文件、参考图和可选 mask
3. 将 `configs/task.json` 写成：

```json
{
  "task_file": "tasks/<任务名>/task.json"
}
```

4. 执行 `python main.py`

## 配置字段说明

`configs/task.json` 使用以下字段：

```json
{
  "prompt_name": "default",
  "prompt_version": "",
  "variables_file": "prompts/variables/example.json",
  "reference_images": [],
  "mask_image": "",
  "image_size": "3840x2160",
  "image_format": "png",
  "image_count": 1
}
```

或使用任务指针：

```json
{
  "task_file": "tasks/CiHuaQianQiu/task.json"
}
```

字段约定：

- `prompt_name`：提示词名称，对应 `prompts/templates/` 与版本索引
- `prompt_version`：可选；留空时读取 `configs/prompt_versions.json` 中的 `latest`
- `variables_file`：变量文件路径，必须位于项目目录内
- `reference_images`：参考图路径数组，支持 0~N 张
- `mask_image`：可选 mask 路径；仅在编辑模式下使用
- `image_size`：当前任务尺寸，可单次覆盖默认值
- `image_format`：当前任务输出格式
- `image_count`：当前任务输出张数
- `task_file`：真实任务配置文件路径，相对于项目根目录

路径解析规则：

- 直接写在 `configs/task.json` 中的普通任务配置，仍按项目根目录解析
- 指针式 `configs/task.json` 中的 `task_file`，按项目根目录解析
- `tasks/<任务名>/task.json` 中的 `variables_file`、`reference_images`、`mask_image`，按该任务目录解析

模式判定规则：

- `reference_images=[]`：文本生图
- `reference_images` 非空且 `mask_image` 为空：参考图生图
- `reference_images` 非空且 `mask_image` 非空：编辑模式

## 最小示例

### 1. 纯文本生图

```json
{
  "prompt_name": "default",
  "prompt_version": "",
  "variables_file": "prompts/variables/example.json",
  "reference_images": [],
  "mask_image": "",
  "image_size": "3840x2160",
  "image_format": "png",
  "image_count": 1
}
```

### 2. 单张或多张参考图生图

单张参考图时，`reference_images` 只保留 1 个路径即可。多张参考图时，继续按优先级往后追加。

```json
{
  "prompt_name": "default",
  "prompt_version": "",
  "variables_file": "prompts/variables/example.json",
  "reference_images": [
    "examples/reference_images/reference_main.png",
    "examples/reference_images/reference_style.png"
  ],
  "mask_image": "",
  "image_size": "3840x2160",
  "image_format": "png",
  "image_count": 1
}
```

推荐顺序：

- 第 1 张：主体角色、主体风格或主构图
- 第 2 张及以后：服装、配色、材质、局部细节等补充参考

### 3. 多参考图 + mask 编辑

```json
{
  "prompt_name": "default",
  "prompt_version": "",
  "variables_file": "prompts/variables/example.json",
  "reference_images": [
    "examples/reference_images/reference_main.png",
    "examples/reference_images/reference_style.png"
  ],
  "mask_image": "examples/reference_images/mask.png",
  "image_size": "3840x2160",
  "image_format": "png",
  "image_count": 1
}
```

## 输出结果如何验收

每次任务都会写入独立目录：

```text
outputs/YYYY-MM-DD/YYYYMMDD_HHMMSS_task_xxxxx/
```

建议按以下顺序检查：

1. `prompt/final_prompt.md`：确认最终提示词是否符合预期
2. `api/request.json`：确认模型、尺寸、参考图路径顺序、mask 路径
3. `api/response.json`：确认接口是否返回图像数据或错误摘要
4. `images/`：确认图片是否成功落盘
5. `metadata.json`：确认 `status`、`image_paths`、`reference_image_paths`、`mask_image_path`
6. `logs/task.log`：确认请求摘要、响应摘要、异常堆栈

## 常见失败排查

### 路径错误

典型现象：

- `variables_file 对应文件不存在`
- `reference_images[0] 对应文件不存在`
- `mask_image 对应文件不存在`

处理方式：

- 确认文件已放在项目目录内
- 确认 `configs/task.json` 中填写的是项目内相对路径
- 不要填写盘符绝对路径

### 图片后缀不支持

典型现象：

- `reference_images[0] 必须是图片文件`
- `mask_image 必须是图片文件`

处理方式：

- 改用 `.png`、`.jpg`、`.jpeg` 或 `.webp`

### `mask_image` 缺少参考图

典型现象：

- `提供 mask_image 时，reference_images 不能为空`

处理方式：

- 编辑模式必须至少提供 1 张参考图

### API 请求失败或响应无图像数据

典型现象：

- `api/response.json` 中只有错误摘要
- `logs/task.log` 中出现接口异常或响应格式异常

处理方式：

- 先检查 `final_prompt.md` 与 `api/request.json`
- 再检查 API Key、网络和模型权限
- 如任务失败，优先以 `metadata.json` 的 `status` 与 `error` 为准

## 协作约定

- 每次新需求先复制配置模板，不直接覆盖历史任务目录中的任何文件
- 每次新需求单独准备变量文件和参考图素材，避免多人共用同一份临时配置
- 推荐将真实需求统一落在 `tasks/<任务名>/`，由 `configs/task.json` 指向当前任务
- 示例配置中的 `examples/reference_images/` 为占位素材，只用于演示路径写法和数组结构
- 如果要复现某次任务，优先查看该任务目录中的 `prompt/`、`api/`、`metadata.json` 与 `logs/task.log`
